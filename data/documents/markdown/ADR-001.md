# ADR-001 — Event Streaming Architecture
## Status
Accepted — Version 2.0
## Decision
Apache Kafka is the primary event streaming backbone for high-volume asynchronous domain events. RabbitMQ remains approved for low-volume task queues where acknowledgement and routing semantics matter more than replayable event history.
## Why Kafka
Kafka is preferred when an event is a durable fact that multiple consumers may process independently. Consumers can replay events from offsets after processing failures.
## Why Not Kafka Everywhere
Kafka is not the default for short-lived command queues. RabbitMQ is simpler for small task-oriented workloads.
## Operational Constraints
Payment events use `payments.v2`. Producers include `event_id`, `event_type`, `occurred_at`, and `schema_version`. Consumers must be idempotent.
